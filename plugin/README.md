# Claude adapter

This is an experimental Claude Code **mod**, using `session.compact` to select the input to Claude's native LLM summarizer. It is not a classic `PreCompact` shell hook and does not edit transcript files on disk.

The current official mod tutorial requires **Claude Code 2.1.287 or later**. API declarations are early access and can change. Context Loom checks the host version and context APIs at startup, and falls back to ordinary native compaction when its worker or selection adapter is unavailable. The plugin must be tested against declarations generated by the exact Claude build before release.

## Flow

1. Read measured context usage. Unknown usage stays unknown.
2. At 70% by default, schedule compaction at an idle boundary. A guard, ten percentage point hysteresis and a one minute cooldown prevent repeated triggers.
3. Send the current compaction event's messages to the authenticated local selection worker.
4. Pass selected **original handles**, together with summary instructions, to Claude's native summarizer.
5. Keep the generated summary and append protected, pinned and recent original messages in their original order. Tool calls and results stay together.
6. Validate the replacement conservatively. If custom retention cannot be validated, retain the native summarizer's result and report that custom retention was not applied. A summarizer error skips compaction and preserves the original context, rather than retrying the model invisibly.

The local UTF-8 byte guard is conservative and is not an authoritative model token count. The host's system instructions and tool definitions are outside the adapter's conversation budget. The conversation target is 40% of the host window, capped at the worker limit of 200,000 estimated text tokens. The native summary planning reserve starts at 2,048 estimated text tokens; this is an initial configuration, not a measured optimum. Protected messages can force a larger retained context than requested; native fallback is reported rather than claiming a successful custom budget.

## Commands

Use Claude's built-in **`/compact`** for the verified native path. The mod intercepts its `session.compact` event and applies relevance selection, native LLM summarization and declared retention.

- `/loom-status` shows adapter readiness, measured usage and current message IDs. It does not print transcript content or credentials.
- `/loom-pin latest` retains the latest user text verbatim. `/loom-pin m0 m4` pins specific IDs displayed by `/loom-status`. Pins follow content identity across changed indices; they last for the current loaded mod instance and reset on reload.
- `/loom-compact` queues manual compaction after its command handler returns, then tries an idle boundary. Host boundary rejections retry at most five times; `/loom-status` reports completion or the final failure. The headless streaming test rejected these API attempts; this convenience command remains unverified in an interactive terminal. Use built-in `/compact` for the tested path.
- `/loom-recall snapshot_id` lists historical message IDs and roles. Add specific IDs, for example `/loom-recall snapshot_id m0 m4`, to retrieve those original rows as labeled historical evidence. Responses are bounded to 16,000 UTF-8 bytes; request fewer IDs when needed. The worker keeps at most 16 snapshots in RAM for 60 minutes; they do not survive a worker restart. The continuation summary and status include the recovery reference.

## Configuration

The launcher sets the worker URL and a per-process token in the child environment. No token is written to the plugin or transcript. TLS certificate verification remains enabled; the launcher supplies the local CA through the host's supported trust mechanism.

| Variable | Default |
| --- | --- |
| `CONTEXT_LOOM_WORKER_URL` | `https://localhost:8787` |
| `CONTEXT_LOOM_WORKER_TOKEN` | Required, supplied by launcher |
| `CONTEXT_LOOM_THRESHOLD` | `0.70` |
| `CONTEXT_LOOM_TARGET_RATIO` | `0.40` |
| `CONTEXT_LOOM_RECENT_MESSAGES` | `4` |

Only HTTPS loopback worker URLs are accepted. The worker endpoint is `POST /v1/plan`, authenticated using `Authorization: Bearer ...`. The plugin does not send history to the portfolio website. Native LLM summarization uses the coding agent's existing model credentials and may incur that model's normal usage charges.

The recent-message setting accepts 1 through 40. Unknown usage prevents automatic threshold compaction; a native manual compaction can still supply history. HTTP waits time out after 15 seconds using the supported host timer API. Claude2.1.288 does not expose request cancellation in `HttpInit`, so an already-started read-only worker request may finish after that deadline.

## Verification so far

- The installed Claude CLI is **2.1.236**, below the documented mod requirement.
- `claude plugin validate --strict .../plugin` passes the legacy manifest validator after including an empty `hooks` envelope. This version does **not** validate or execute the new `modules` entry and provides no proof of native mod integration.
- Node tests with fake host APIs cover selection, tool grouping, verbatim retention, stable pins, unknown usage, hysteresis, worker failure and model failure. These are unit tests, not a real terminal session or real LLM compaction benchmark.
- An isolated **2.1.288** CLI passed strict validation of the actual module events, API calls and environment reads. A non-persistent `/loom-status` run loaded the module and returned readiness from the live version/usage APIs, with usage correctly shown as unknown before any model response. No model summarization or TLS worker exchange was exercised by that command.
- A synthetic snapshot created with the **lexical overlap baseline** worker was retrieved through a real isolated2.1.288 `/loom-recall` invocation. `$.http.fetch` used verified TLS through `NODE_EXTRA_CA_CERTS` and bearer authentication; the command returned the expected historical index `m0:user, m1:assistant`. This proves the local transport and recall integration, not Qwen ranking or native LLM summarization.
- A real **Qwen3-Reranker-0.6B** worker and isolated **Claude Code 2.1.288 / Claude Haiku 4.5** completed a synthetic native compaction through the built-in `/compact` command. The live status reported selection of 10/10 source messages and retention of 6 original messages. Authenticated snapshot index/row recall returned the original fixture, and the model's follow-up answer preserved `/fixture/v1` and `BUG-123`. The run used verified loopback TLS, disabled tools, no session persistence and an explicitly controlled synthetic system prompt. Recorded evidence is [native-smoke.json](../evaluation/native-smoke.json).
- The tiny native smoke grew from **940 to 1423 host-reported tokens**; its compaction boundary reported **13.781 seconds**. This establishes integration on a small fixture. It demonstrates no context savings, no broad semantic fidelity and no general benchmark improvement.
- The headless `/loom-compact` API route rejected five bounded attempts. Its interactive idle behavior and a real 70% automatic-threshold trigger remain **unverified**; unit tests cover the scheduling and safety logic.
- No global Claude installation, settings or hooks were changed.

Before release, validate against each supported host build, then exercise larger histories, interactive idle triggering and threshold compaction. Keep compatibility, integration smoke results and effectiveness benchmarks separate.

`tests/live_probe.py` exercises a small synthetic, non-persistent session with tools disabled, an explicit synthetic test system prompt and a $0.50 default budget ceiling. This isolates the integration fixture from repository or enterprise instructions; it does not establish ordinary terminal-session adoption. It requires an explicitly supplied supported `--claude` executable, the launcher's `CONTEXT_LOOM_WORKER_TOKEN` and `NODE_EXTRA_CA_CERTS`. It polls bounded completion status after the deferred manual request and reports observed native compaction, snapshot recall, echoed input and fixture identifiers; it is not a benchmark. The default model is the host's `haiku` alias and can be changed with `--model`.
